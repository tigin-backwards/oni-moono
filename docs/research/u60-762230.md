# U60 762230: entombed items, power banks and destroyed objects

Build 762230 replaced 762107 on Steam's `public_testing` branch on 2026-11-06. It is a
hotfix: the three fixes of the patch notes and the build number. `Assembly-CSharp.dll` and
`Assembly-CSharp-firstpass.dll` changed among the managed assemblies; every Unity module and
package, the BCL and the other libraries are 762107's bytes, and the Unity version is still
6000.3.17f1. The `u60` branch now targets 762230; this page is the delta, its impact on Moono,
the QA plan and its results.
`u60-762107.md` covers the build before it.

## Summary

- **Moono plays 762230.** `u60` loads early-base and plays 180 game seconds at speed 3 on
  Linux in both players; every IL rewriter's count and every game tweak's install line is
  762107's (see "Smoke test"). The Unity version is unchanged (6000.3.17f1), so the version
  check lets the current `u60` release start on 762230 too.
- **No public API changed:** AssemblyDiff finds no difference in Assembly-CSharp or firstpass;
  `tools/Inventory` is the same; the fixes are inside method bodies.
- **The "recently destroyed objects" crash** is the U60 Disease overlay crash our
  `fix-disease-overlay-crash` worked around: `CellChangeMonitor.RenderEveryTick` now drops a
  destroyed object's entry before reading its transform, for every entry the tweak handled and
  more. UnityProbe `cellchangecrash`, which reproduces it, throws in the 762107 original and
  runs clean in the 762230 original and in ours, the same frames. The tweak is removed from
  `u60` (retired, no replacement).
- **The Auto-Sweeper fix** (FetchAreaChore skips entombed items; `Pickupable.OnStore` clears
  the entombed status) and **the Power Bank fix** (an empty bank in a solid cell moves to the
  Bionic's cell before it is dropped) are game code. Neither touches a method
  `instant-reachability` hooks, nor changes the shape of one: its stress spec with
  `ONI_TWEAK_VERIFY=1` has 0 mismatches in 61.8 million checks on 762230.
- **QA:** smoke, `unreachable-materials`, `klei-unreachable` and Y1 (an entombed item stored)
  pass in both players on Linux; `u60/vk-gate` and the stress spec pass in ours. Windows: both
  players load early-base and play 180 s at speed 3, ours on Vulkan from the release build.
  check.sh is green on 762230.

## The destroyed-object fix

What Klei's check needs from the engine: that `kobj.gameObject == null` is true once the object is
destroyed, through `UnityEngine.Object`'s `==` (the field still holds the managed object), and
that the destroyed object is still registered when `RenderEveryTick` (in `Game.Update`) next runs.
Both are what our `fix-disease-overlay-crash` already relied on (it read `kobj.gameObject != null`
the same way), and the second is when destruction is carried out, which the engine matches
(`Lifecycle.ProcessDestroyQueue`, measured with UnityProbe `destroycascade` and
`cellchangecrash`).

**Klei's change covers the tweak's case.** The tweak's prefix walked
`pendingDirtyTransforms` before `RenderEveryTick` and unregistered each id whose KObject had no
pending cell (`pendingCell == -1`) and a `GameObject` that compared equal to null. The first
thing `RenderEveryTick` does is swap `pendingDirtyTransforms` into `dirtyTransforms`
(fp762230:CellChangeMonitor.cs:328), so its loop visits the same ids, and 762230's check removes
an entry whose `GameObject` compares equal to null whatever its pending cell
(fp762230:CellChangeMonitor.cs:337-341). An entry the tweak removed is one 762230 removes; 762230
also skips a destroyed object that has a pending cell (which did not throw, but raised its
`CellChanged` event and its movement-state handlers) and no longer counts it as moving. The
throw itself was the read at fp762230:CellChangeMonitor.cs:345, which now only live objects reach.

Measured (2026-11-06, `ccprobe-762230.yaml`, not committed: UnityProbe `cellchangecrash` at
the main menu, `SemanticsProbe.dll` in a copy of OniMcp's mod folder, `PROBE_SCENARIO` through
the spec's `env` for ours and `E2E_ORIGINAL_ENV` for the original; run ids `cc762230b`,
`cc762107b`):

| Player | Phase 1 (no fixed step next frame) | Phase 2 (fixed steps every frame) |
|---|---|---|
| Original 762107 | ok, child alive, then ok twice (child null) | **threw NullReferenceException** (child null), then ok twice |
| Original 762230 | the same | ok three times (child null) |
| Ours on 762230 | the same | ok three times (child null) |

So Klei's check covers the case the tweak handled (the destroyed child's KObject, no pending
cell, read in the next `Game.Update`), and ours gives the same frames as the original: the
child is gone by the next `RenderEveryTick` in both, `== null` is true for it in both.

## instant-reachability

`instant-reachability` (src/OniMoono.GameTweaks/InstantReachability.cs) patches
`ReachabilityMonitor.InitializeStates`, `MinionGroupProber.OnPrefabInit`, `Occupy` (both
overloads), `OccupyST`, `Vacate` (both), `VacateST`, `Pickupable.UpdateCachedCell`,
`Workable.SetOffsets`, `Workable.SetOffsetTable`, `OffsetTableTracker.OnCellChanged`,
`OffsetTracker.ForceRefresh` and `Game.Update`, and stands down when another owner patches its
guarded methods (the same list plus `ReachabilityMonitor.Instance.UpdateReachability`,
`MinionGroupProber.IsReachable`/`IsAllReachable`, `Workable.GetCell`/`GetOffsets`,
`Pickupable.GetCell`, `Diggable.GetCell`, `Unsealable.GetOffsets`, `OffsetTracker.GetOffsets`,
`OffsetTableTracker.UpdateOffsets`/`UpdateCell`).

- **Shapes:** AssemblyDiff finds no difference in either assembly, so every one of these methods
  and the fields the tweak reads (`Workable.offsetTracker`, `OffsetTracker.offsets`,
  `OffsetTableTracker.table`/`cmp`, `MinionGroupProber.cells`) keeps its signature.
- **Bodies:** none of them is in the diff. `SolidTransferArm` (which writes the prober's table
  through `Occupy`/`Vacate` with its reachable cells) is unchanged, and so are
  `FetchableMonitor`, `ReachabilityMonitor`, `MinionGroupProber`, `OffsetTracker`,
  `OffsetTableTracker` and `Workable`.
- **Callers:** the one changed method that reaches a hook is `Pickupable.OnStore`, which calls
  `UpdateCachedCell(Grid.PosToCell(storage))` as before, now after clearing `IsEntombed`. The
  entombed status is not an input of reachability (`IsAllReachable` of the cell and offsets);
  it is an input of fetchability (`FetchableMonitor.IsFetchable`, its `EntombedChanged`
  transitions), which the tweak doesn't touch. `IsEntombed = false` in `OnStore` triggers
  `EntombedChanged`, and FetchableMonitor reads `IsReachable()`, the tweak's answer, as before.
  The Bionic fix moves a bank by `Transform.SetPosition` while it is still stored, then drops it:
  the drop's `OnStore(null)` leads to `UpdateCachedCell` at its new cell, which the tweak follows
  (a `Pickupable`'s cell is its cached cell; the move flags are not used for it).
- **Measured:** the stress spec with `ONI_TWEAK_VERIFY=1`, and Y1 with the tweak on (the users'
  default), in "QA results".
