# U60 763325: a fixes patch to 763023

Build 763325 replaced 763023 on Steam's `public_testing` branch on 2026-11-16. Klei's notes list
six changes and fourteen fixes. It is a small patch:

- **Changed:** `Assembly-CSharp.dll` (42 files in the decompile), the DLC bundles, the strings,
  the serialized data, and on Windows SimDLL's build stamp.
- **Unchanged:** `Assembly-CSharp-firstpass.dll`, every Unity module and package, the BCL, the
  other libraries, the FMOD banks and libraries, and the Linux `libSimDLL.so` are 763023's bytes.
  The Unity version is still 6000.3.17f1.

The `u60` branch now targets 763325. This page is the delta, its impact on Moono, and the QA
results. `u60-763023.md` covers the build before it. U59 (the default branch) did not change:
its main depot's manifest is still 744825's (4837644823067158760, 2026-07-28), so `master` is
untouched.

Sources:
- Klei's decompiled game code in oni-archives: `changed_members U60-763023 U60-763325`.
  `763325:raw/Assembly-CSharp/File.cs:N` is a line of that file at tag U60-763325. Firstpass is
  the same bytes as 763023's.
- The frozen builds `E:\oni-builds\oni-linux-763023`, `oni-linux-763325`, `oni-win-763023` and
  `oni-win-763325`, every file compared by MD5 (Linux 1,629 files in both, Windows 1,741 in both;
  `.DepotDownloader` left out).
- `--check-tweaks review` on both 763325 builds and both 763023 builds, and its normalised
  listings of every fingerprinted body (`out/tweak-review/BUILD/`).
- The serialized files' objects listed with UnityPy (type, name, path ID, size and an MD5 of
  each object's bytes), both Linux builds.
- `tools/AssemblyDiff` on the Linux builds' Assembly-CSharp, 763023 against 763325, and Linux
  against Windows.
- Klei's patch notes for the build, as the user pasted them.

Claims not checked against one of these are marked "not verified".

## Summary

- **Moono plays 763325 without a code change.** No fingerprinted body differs from 763023's (the
  123 normalised listings are the same bytes on both builds, Linux and Windows), every tweak
  passes the file checks and installs on both 763325 builds, and no changed method is one a
  tweak patches or mirrors.
- **Version check:** the Unity version is unchanged, so the current `u60` release starts on
  763325 too. Its tweaks all install there: `check-tweaks` on `u60` before the retarget (the
  commit the u60 release draft was built from) passes on 763325.
- **Public API:** nothing mods can bind to is gone. `IBlueprintInfo` gains an abstract
  `displayDlcId` property, which breaks only a mod that implements the interface (see "Mods").
- **The fixes** are game code that both players run the same way. The two that rely on engine
  behaviour, the planter side screen's coroutine and the rocket's next-frame deletion, rely on
  behaviour Moono's engine matches (see "The host, the engine and our API").
- **QA:** check.sh and check-tweaks pass on every U60 build. The Linux quick QA (smoke, V1, the
  Vulkan gate) and a Windows Vulkan smoke on a late-game save pass (see "QA results").

### Changes the notes do not mention

- **Cosmetic permits name their pack.** `IBlueprintInfo.displayDlcId` (and on each info class and
  `ClothingOutfitResource`), `BlueprintProvider.SetDisplayDlcId`, and
  `BlueprintCollection.FindBlueprintInfo`/`GetDisplayDlcId`/`GetAllDisplayDlcIds`.
  `PermitResource.GetDlcIdFrom` prefers the display id. Every Hatch permit in
  `Blueprints_CosmeticPack2_U60` is marked `COSMETIC2_ID`; the provider is still not in
  `Blueprints.skinsReleaseProviders`, so the permits stay dormant.
- **Facades on artworks.** `BuildingFacade.ClearFacade` keeps an `Artable` with a stage other than
  `Default` as it is, instead of restoring the building's own anim
  (763325:raw/Assembly-CSharp/BuildingFacade.cs:54-58).
- **Crash reports and mods.** `KMod.Manager` set `KCrashReporter.haveActiveMods` after recycling the
  pooled list, so it was always false; it now reads the count first
  (763325:raw/Assembly-CSharp/KMod.Manager.cs:1306).
- **The build number** 763023 → 763325: `KleiVersion.ChangeList`, `SaveGame.GetSaveHeader`,
  `Game` (twice), `Global`, `KCrashReporter`, `KMod.Mod.GetMostSuitableArchive`, `LoadScreen`
  (three places), `MainMenu`, `BuildWatermark`, `PerformanceCaptureMonitor`. The save minor
  version stays 39. One `[Serialize]` change: the Trampoline's state machine now saves its
  parameters.

## Game tweaks and IL rewriters

`check-tweaks --review` on `linux-763325`, `win-763325`, `linux-763023` and `win-763023`:

- On all four, 50 of 50 tweaks pass the file checks and install, and the Moono Tweaks menu
  installs; 543 name lookups checked, none undeclared.
- The 123 normalised listings of fingerprinted bodies are the same bytes on all four builds.
- Each accepted fingerprint now lists `linux-763325` and `win-763325`.

The types Klei changed that our code names are `WorldInventory`, `Game`, `LoadScreen` and
`MainMenu`. In the last three only build constants changed, in bodies no tweak fingerprints.
`direct-rail-bridges` mirrors `WorldInventory.OnAddedFetchable` and stands down when another
owner patches it: its body is unchanged; only how the inventory subscribes it changed (a static
delegate that calls it, and a working unsubscribe).

`fmod-steal-fix` patches FMOD Studio only when its library's SHA-256 matches: 763325's
`fmodstudioL.dll` and `libfmodstudioL.so` are 763023's files, so its U60 rows now name 761015
to 763325.

The IL rewriters match methods by name and signature; on 763325 ours logs `game conversions:
Assembly-CSharp.dll: 517 conversion(s) of floats in 278 method(s)` and firstpass 97 in 52, as on
763023.

## The host, the engine and our API

- **Version check.** `GameVersionCheck` compares the data's Unity version (6000.3.17f1 → U60);
  unchanged.
- **Natives.** SimDLL's Windows DLL differs from 763023's in 30 bytes, as in the updates before
  (the build stamp). The Linux `libSimDLL.so` is the same bytes.
- **The Workshop item.** Its U60 version now asks for build 763325 (`minimumSupportedBuild`); the
  loader mod builds against 763325's reference assemblies. An item that asks for 763023 still
  loads on 763325 (the game takes the newest version whose build is not above its own).
- **Engine.** The new code calls no engine member that 763023's did not (AssemblyDiff: no type or
  member of Unity's added or gone in the game's references). `PlanterSideScreen` checks
  `activeInHierarchy` before `StartCoroutine`; Moono's `Coroutines.Start` logs Unity's error and
  returns null for an inactive object, as Unity does. `CraftModuleInterface` defers through the
  game's own `UIScheduler`.
- **Linux and Windows agree.** AssemblyDiff of the two builds' Assembly-CSharp: one difference,
  the Windows-only `Global.saveFolderTestResult`, as on 763023.

## Mods

- **Gone:** nothing public. Only compiler-generated lambdas of `BlueprintCollection` and
  `PlanScreen` were renumbered.
- **Changed:** `IBlueprintInfo` gains `displayDlcId { get; set; }`. A mod type that implements
  the interface fails to load (`TypeLoadException`) in both players; none is known.
- **Added:** the permit members above, `SpiceGrinderWorkable.AddSpeedModifier`/
  `RemoveSpeedModifier`/`GetTotalSpeedModifier`, `SupportBuildingBoost_KitchenSpeed.ApplyBoost`/
  `RemoveBoost` overrides, `Trampoline.isFilled`/`hasBeenOperational` and
  `Trampoline.Instance.manualDelivery`, and private fields and helpers.
- **Constants** compiled into mods keep their old values: `TrampolineConfig`'s delivery minimum,
  `SandboxBuildingConfig`'s stage lists (static arrays, read at run time), `KleiVersion.ChangeList`.
- **Still gone in every U60 build:** `LocText.ModifyLinkStrings` (firstpass, unchanged) and
  `PlantAttributes.YieldAmount`. The mod table's rows for them now say 761015 to 763325.
- **The mod gate** reads onimaxxing's data for the game folder's build. onimaxxing has none for
  763325 yet (`catalog.json` answers 404; 763023's now answers 200), so on `u60` every mod with
  binaries is skipped until it does. `ONI_GAME_BUILD=763023` uses 763023's reviews, which are of
  the uploads, whatever the build.
