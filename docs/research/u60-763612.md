# U60 763612: a small fixes patch to 763325

Build 763612 replaced 763325 on Steam's `public_testing` branch on 2026-11-17 (Steam build
26744932). Klei's notes list three fixes and touch-ups for every version, one for Spaced Out and
two for the Aquatic pack. It is a smaller patch than 763325:

- **Changed:** `Assembly-CSharp.dll` (13 files in the decompile, 10 of them only the build
  number), the Simplified Chinese strings, the serialized data (`globalgamemanagers`,
  `resources.assets`, `sharedassets0.assets` and their `.resS`), and on Windows SimDLL's build
  stamp. Only the main depot changed; every DLC depot is 763325's manifest.
- **Unchanged:** `Assembly-CSharp-firstpass.dll`, every Unity module and package, the BCL, the
  other libraries, the FMOD banks and libraries, the DLC bundles, `level0`, the Linux
  `libSimDLL.so` and the other `sharedassets*.assets` are 763325's bytes. The Unity version is
  still 6000.3.17f1.

The `u60` branch now targets 763612. This page is the delta, its impact on Moono, and the QA
results. `u60-763325.md` covers the build before it. U59 (the default branch) did not change:
its main depot's manifest is still 744825's (4837644823067158760, 2026-07-28), so `master` is
untouched.

Sources:
- Klei's decompiled game code in oni-archives: `changed_members U60-763325 U60-763612`.
  `763612:raw/Assembly-CSharp/File.cs:N` is a line of that file at tag U60-763612. Firstpass is
  the same bytes as 763325's.
- The frozen builds `E:\oni-builds\oni-linux-763325`, `oni-linux-763612`, `oni-win-763325` and
  `oni-win-763612`, every file compared by MD5 (Linux 1,629 files in both, Windows 1,741 in both;
  `.DepotDownloader` left out).
- `--check-tweaks review` on both 763612 builds and both 763325 builds, and its normalised
  listings of every fingerprinted body (`out/tweak-review/BUILD/`).
- The serialized files' objects listed with UnityPy (type, name, path ID, size and an MD5 of
  each object's bytes), both Linux builds; and each `Texture2D`'s pixels in the `.resS` files
  (dimensions, size and MD5), which an object's own bytes do not cover.
- `tools/AssemblyDiff` on the Linux builds' Assembly-CSharp, 763325 against 763612, and Linux
  against Windows.
- Klei's patch notes for the build, as the user pasted them.

Claims not checked against one of these are marked "not verified".

## Summary

- **Moono plays 763612 without a code change.** No fingerprinted body differs from 763325's (the
  126 normalised listings are the same bytes on both builds, Linux and Windows), every tweak
  passes the file checks and installs on both 763612 builds, and no changed method is one a
  tweak patches or mirrors.
- **Version check:** the Unity version is unchanged, so the current `u60` release starts on
  763612 too. Its tweaks match by fingerprint, and no fingerprinted body changed.
- **Public API:** nothing mods can bind to is gone or added. AssemblyDiff finds no difference in
  Assembly-CSharp's shape between 763325 and 763612.
- **The fixes** are game code that both players run the same way: a sweep sort that now ranks
  by priority class, a rocket speed with no modules, and a Merpip egg entry for the Cuddle Pip.
  None relies on engine behaviour the earlier builds did not.
- **QA:** check.sh and check-tweaks pass on every U60 build. On Linux the V1 build check and
  the Vulkan gate pass, and the smoke passes every check but its screenshot comparison, which
  fails the same way on 763325 (see "QA results"). The Windows Vulkan smoke on a late-game save
  passes.

## Game tweaks and IL rewriters

`check-tweaks --review` on `linux-763612`, `win-763612`, `linux-763325` and `win-763325`:

- On all four, 52 of 52 tweaks pass the file checks and install, and the Moono Tweaks menu
  installs; 559 name lookups checked, none undeclared. One lookup is not checked on every build
  alike: `ProbeRepair`'s static constructor enumerates `Grid.SuitMarker`'s fields, not yet marked
  reviewed. It is the same on 763325 and has nothing to do with this build.
- The 126 normalised listings of fingerprinted bodies are the same bytes on all four builds.
- Each accepted fingerprint now lists `linux-763612` and `win-763612`.

The types Klei changed that our code names are `Game`, `LoadScreen` and `MainMenu`, where only
build constants changed: in `Game.OnPrefabInit` (postfixed by `fast-smi-lookups` and
`fetch-by-cell`, not fingerprinted) and in `LoadScreen` and `MainMenu` bodies no tweak
fingerprints. `ClearableManager`, `Clustercraft` and `SquirrelTuning` are named nowhere in
`src/`.

`fmod-steal-fix` patches FMOD Studio only when its library's SHA-256 matches: 763612's
`fmodstudioL.dll` and `libfmodstudioL.so` are 763325's files, so its U60 rows now name 761015
to 763612.

## The host, the engine and our API

- **Version check.** `GameVersionCheck` compares the data's Unity version (6000.3.17f1 → U60);
  unchanged.
- **Natives.** SimDLL's Windows DLL differs from 763325's in 29 bytes, as in the updates before
  (the build stamp). The Linux `libSimDLL.so` is the same bytes.
- **The Workshop item.** Its U60 version now asks for build 763612 (`minimumSupportedBuild`); the
  loader mod builds against 763612's reference assemblies. An item that asks for 763325 still
  loads on 763612 (the game takes the newest version whose build is not above its own).
- **Engine.** The new code calls no engine member that 763325's did not: a comparison on two
  fields, a list count and a float return.
- **Linux and Windows agree.** AssemblyDiff of the two builds' Assembly-CSharp: one difference,
  the Windows-only `Global.saveFolderTestResult`, as on 763325.

## Mods

- **Gone, changed or added:** nothing (AssemblyDiff: 0 differences, 763325 to 763612).
- **Constants** compiled into mods keep their old values: `KleiVersion.ChangeList`.
  `EGG_CHANCES_HUG` is a static list, read at run time.
- **Still gone in every U60 build:** `LocText.ModifyLinkStrings` (firstpass, unchanged) and
  `PlantAttributes.YieldAmount`. The mod table's rows for them now say 761015 to 763612.
- **The mod gate** reads onimaxxing's data for the game folder's build. onimaxxing has none for
  763612 (`catalog.json` answers 404, as 763325's still does; 763023's answers 200), so on `u60`
  every mod with binaries is skipped until it does. `ONI_GAME_BUILD=763023` uses 763023's
  reviews, which are of the uploads, whatever the build.
