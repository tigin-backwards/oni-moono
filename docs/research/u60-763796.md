# U60 763796: the release build of 763612

Build 763796 replaced 763612 on 2026-11-19 (Steam build 26770249, main depot manifest
2743946485976795085), on both `public` and `public_testing`: U60 is now the public game. It is a
release (non-development) build of what is essentially 763612's code. Klei's notes list three
items: the free Hatch blueprints of the Classic Critter Cosmetics Pack, a special case for
hysteresis thresholds of 0 on the Gas and Liquid Reservoirs and the Smart Storage Bin, and a
crash fix when Kitchen Tools and a backwall near a cooking station are destroyed.

- **Changed:** both game assemblies and every other managed library Klei compiles or ships
  (TextMeshPro, UnityEngine.UI, Timeline, Burst, Collections, Mathematics, ImGui, FMODUnity,
  Steamworks.NET), UnityPlayer and the executable, the Mono runtime on Windows, SimDLL on
  Windows (the Linux `libSimDLL.so` is 763612's bytes), the Russian strings, and the serialized
  data. Every `.pdb` but SimDLL's, `d3d12SDKLayers.dll`, `WinPixEventRuntime.dll` and the Linux
  `_s.debug` files are gone, and so is `globalgamemanagers.assets.resS`. FMOD Studio is no longer the logging build: `fmodstudioL` is
  replaced by `fmodstudio`, the same bytes as U59 744825's. A new DLC depot holds the cosmetic
  pack (`cosmetic2_bundle`, `hires_cosmetic2_bundle`, `dlc/cosmetic2`).
- **Unchanged:** the Unity version (6000.3.17f1), the FMOD banks, the other DLC bundles.

The `u60` branch now targets 763796. This page is the delta and its impact on Moono. The
procedure ran without its QA runs (§6), at the owner's request: check-tweaks, check.sh and the
unit tests as CI runs them are the evidence.

Sources:
- Klei's decompiled code in oni-archives: `changed_members U60-763612 U60-763796` (run with
  `tools/query.py` directly; the MCP server's `changed_members` and `diff_member` failed with "too
  many values to unpack" on every pair), and `git diff U60-763612 U60-763796 -- norm` in its
  `history/`. Tag U60-763796 is committed locally in oni-archives but not pushed (its gate
  compared it with U59-744825, the previous release-branch build, and failed).
- The frozen builds `E:\oni-builds\oni-linux-763612`, `oni-linux-763796`, `oni-win-763612` and
  `oni-win-763796`, every file compared by MD5 (`.DepotDownloader` left out).
- `check-tweaks --review` and `--check-tweaks declare` on both 763796 builds and both 763612
  builds, and the normalised listings of every fingerprinted body (`out/tweak-review/BUILD/`).
- `tools/AssemblyDiff` on the Linux builds' managed libraries, 763612 against 763796, and
  Assembly-CSharp Linux against Windows.

## Summary

- **Moono plays 763796 with new fingerprints only.** No fingerprinted body's code changed. The
  release compiler's IL differs from the development build's (no `nop`s, fewer temporaries,
  branches folded), so 58 of the 140 fingerprinted bodies have new hashes; the other 82 are
  U59 744825's hashes, U59 being a release build of the same source. With the new hashes every
  tweak passes and installs on both builds, transpilers included.
- **Public API:** AssemblyDiff finds no difference in Assembly-CSharp, firstpass, TextMeshPro,
  UnityEngine.UI, Timeline, Burst, Collections, Mathematics or Steamworks.NET between 763612 and
  763796. FMODUnity's 1,170 differences are its P/Invoke imports, now from `fmodstudio` instead
  of `fmodstudioL`; the host binds both names (`GamePlugins`), as on U59.
- **fmod-steal-fix** applies: 763796's `fmodstudio.dll` and `libfmodstudio.so` are U59's
  files, whose SHA-256 it already knew, and FMOD is still 2.03.12 build 160365.
- **Version check:** the Unity version is unchanged, so the current `u60` release starts on
  763796.

## The code delta

`changed_members U60-763612 U60-763796`: 535 members (433 in Assembly-CSharp, 102 in
firstpass). 356 are `il-only` and 28 `source-only`; of the 143 `changed`, nearly all are the
release compiler's shapes that the normalisation does not fold (a `switch` expression as a
`switch` statement, a condition inverted, a loop variable renamed, a temporary inlined:
`ConduitFlow+SOAInfo::GetConduitFromDirection`, `NavGrid+Transition::IsValid`,
`RequireInputs::CheckRequirements`, `KSerialization.DeserializationMapping::ReadValue`, the
Delaunay, Clipper and Satsuma bodies) and dead `if (1 == 0)` blocks dropped
(`LoadScreen::DoLoad`, `Klei.AI.PartyEvent+States::GenerateEventPopupData`). The real changes:

| Note | Code | Moono |
|---|---|---|

## Game tweaks

`check-tweaks --review` on `linux-763796` and `win-763796` before the new fingerprints: 30 of
53 tweaks passed (their bodies have U59's hashes), 23 were off on changed fingerprints. None of
the 140 fingerprinted bodies is among the members whose normalised code changed, and the Linux
and Windows hashes agree, so each accepted list that names 763612 now names `linux-763796` and
`win-763796`: beside U59's hash for 82 bodies, as a new hash for 58. After that, 53 of 53 pass
the file checks and install on both builds, also with `ONI_TWEAK_VERIFY=1` on Linux.

The one lookup not checked, `ProbeRepair`'s enumeration of `Grid.SuitMarker`'s fields, is as on
763612.

## Mods

AssemblyDiff finds nothing gone or added in Assembly-CSharp or firstpass. onimaxxing has no
data for 763796 (`catalog.json` answers 404, as 763612's still does), so the mod gate skips
every mod with binaries on `u60` until it does.
