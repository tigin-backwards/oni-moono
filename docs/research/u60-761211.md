# U60 761211: the hotfix

Build 761211 replaced 761015 on Steam's `public_testing` branch at the end of October 2026. It
is a small hotfix: a fix to where fish are released, a fix to two transfer loops, and the build
number. The `u60` branch now targets 761211. This page lists the whole delta, what was
retargeted, and what to check again. `u60-inventory.md` covers U60 against U59.

Sources:
- Klei's decompiled game code in oni-versioning: `git diff U60-761015 U60-761211` (`4a63c523`
  to `50066d31`). Both builds are public-test builds, so the diff is only code.
- The frozen builds: `E:\oni-builds\oni-linux-761015`, `oni-linux-761211`, `oni-win-761015` and
  `oni-win-761211`, each file compared by MD5.
- `tools/AssemblyDiff` (type and member shapes) and `tools/Inventory` (what Assembly-CSharp
  references in Unity, the BCL and firstpass), run on 761015's and 761211's Linux assemblies.

## The code delta

Only `Assembly-CSharp.dll` changed. `Assembly-CSharp-firstpass.dll` and every other managed
assembly (Unity's modules, uGUI, TextMesh Pro, Timeline, Mono's BCL) are the same bytes as
761015's, on Linux and on Windows.

1. **Fish release cell.** `CreatureDeliveryPoint.deliveryOffsets` defaulted to the shared static
   `OffsetGroups.Use`. It now defaults to an array of its own, `new CellOffset[1]`, which holds
   the same single (0, 0) cell. `OnSpawn` passes it to `Storage.SetOffsets`, and
   `FishDeliveryPointConfig` still sets its own offsets. This is the fish release cell fix.
2. **Railgun and orbital cargo transfer loops.** `RailGun` (launching a payload) and
   `OrbitalDeployCargoModule` (deploying a payload) filled the payload with a `for` loop whose
   step was `Storage.Transfer(...)`. If a transfer moved nothing while the storage still held
   mass, the loop never ended. Both loops now stop when a transfer moves 0 kg or less.
3. **The build number**, 761015 → 761211, in 11 places:
   - `KleiVersion.ChangeList`;
   - the save header's `buildVersion` (`SaveGame`);
   - `Game.changelistsPlayedOn`, in `OnPrefabInit` and `OnSaveData`;
   - the "save too new" checks in `LoadScreen` (three places) and `MainMenu`;
   - `KMod.Mod`'s choice of an archived mod version (`minimumSupportedBuild <= 761211`);
   - `KCrashReporter`'s report, the KleiMetrics session's `Build`, `BuildWatermark` and
     `PerformanceCaptureMonitor`.

AssemblyDiff finds no difference between the two Linux assemblies' types and members (140,102
lines each). Inventory lists the same references in both builds, by member, to every Unity
module, uGUI, TextMesh Pro, firstpass and the BCL. **Nothing in the delta touches engine surface
Moono implements.** The new code calls `Storage.Transfer` and `MassStored`, both game code. As
in 761015, the Windows assembly differs from the Linux one only in the Windows-only field
`Global.saveFolderTestResult`.

No game tweak patches the changed methods. `OniMoono.GameTweaks` patches `MainMenu.OnPrefabInit`,
which the hotfix left alone, and nothing in `RailGun`, `OrbitalDeployCargoModule`,
`CreatureDeliveryPoint`, `Game`, `SaveGame`, `LoadScreen` or `KleiVersion`.

## What was retargeted

The frozen copies, made as 761015's were (none of them link into the Steam install):
- `~/projects/oni-linux-761211`: the Linux base depot, copied from `E:\oni-builds\oni-linux-761211`.
- `~/projects/oni-dlc-761211`: the DLC `StreamingAssets` entries, copied from
  `E:\oni-builds\oni-win-761211` (the same 53 names as `oni-dlc-761015`).
- `out/local-tools/u60orig-761211` (in the main checkout): the test install, laid out as
  `u60orig`. It links to the two copies and has the DLC-owning Steam double in
  `Plugins/AnyCPU`. Its folder name ends in the build number, so `scripts/mod-gate.py` reads
  761211 when `ONI_GAME_DIR` names it.

In the repository, the default game folder is now `~/projects/oni-linux-761211`:
`Directory.Build.props`, `scripts/env.sh`, `regen-surface.sh`, `unityapi.sh`, `onimcp.py`, and
the test suites' fallbacks (`tests/OniMoono.Assets.Tests`, `tests/OniMoono.UnityEngine.Tests`).
`docs/DEVELOPMENT.md` and `u60-inventory.md` name 761211.

Left on 761015, because they record what happened on it: `tests/e2e/results-u60`, the mod
table's "broken on U60 (build 761015)" notes, the measurements and static reviews in
`ARCHITECTURE.md` and `u60-*.md`, and TextMesh Pro's package notes (the package did not change).
`scripts/check.sh` still looks for the 761015 Mac data (`ONI_MAC_APP`, default
`~/projects/oni-mac-761015`, not on this machine, so the Mac checks are skipped). There is no
761211 Mac download, and the hotfix changed no data the Mac checks read.

## Checked on 761211

- `scripts/regen-surface.sh`: the same output from 761015 and 761211. Its output differs from
  the generated files committed on `u60`, but this drift is older than the hotfix and is the
  same on 761015. Regeneration adds `UnityEngine.Assertions.cs` and `UnityEngine.Profiling.cs`,
  makes `PanelRenderMode` public, adds `TextSettings.FontReferenceMap`, reorders some attributes
  and adds five internal types to `unity-module-map.tsv`. It was not committed here.
- `scripts/unityapi.sh`: the same output from both builds (sampled on `UnityEngine.Transform`).
- `scripts/check.sh` passes on 761211. All unit tests pass (UnityEngine 2,564 with 1 skipped,
  Assets 27, ModTriage 9, scripts OK). The type-load, release check-types (103 ok), assets,
  bind and natives checks pass, and packages show 0 missing. The engine ApiCheck shows the
  13 known UI Toolkit members.
- `scripts/e2e.py --player both geyser-title` on `u60orig-761211` (2026-11-01, run
  `smoke-761211`): both players load `early-base` from the main menu (35 and 36 s), and the
  geyser's details title passes in both. Neither log has an error or exception, and both logs
  name build 761211.

## What to check again

- **Saves cross one way.** A save made on 761211 has `buildVersion` 761211. That includes saves
  made by our player on 761211, because the save header is the game's code. The 761015 game
  (`MainMenu`, `LoadScreen`) calls such a save too new and will not load it. Fixtures blessed on
  761211 must not be used by lanes still on 761015. 761015's saves load on 761211.
- **Mod gate.** onimaxxing publishes `mods-data/761211` (catalog: 3,060 mods, a superset of
  761015's 3,047). After the switch the gate reads 761211's reviews.
- **Mod table.** Its U60 header says "tried on U60 (build 761015)". Once the lanes play on
  761211, say both builds.
- **Mac data.** Fetch depot 457142 at 761211 for the Mac checks, if the Mac data should match
  the target exactly.
- **Windows.** The isolated original for the HDR check (`ORIG_DIR`, `tools/HdrCheck/README.md`)
  and the Windows performance runs still use 761015's copy (`E:\oni-builds\oni-win-761015`).
  Point `ONI_WIN_GAME_DIR` / `ONI_HDR_GAME` at `E:\oni-builds\oni-win-761211` for runs on the
  hotfix.
- **Mods that hash the game assembly.** "Other Half - Mine Yield" checks Assembly-CSharp's hash
  and turned its patch off on 761015. 761211's assembly has another hash again.
