# U60 761654: the .NET Standard 2.1 build

Build 761654 replaced 761211 on Steam's `public_testing` branch on 2026-11-03. It is a content
and fix update with one large change underneath: the game and its libraries are now compiled
against .NET Standard 2.1 instead of .NET Framework. Klei's note: "Mods which were working on the
public beta before this change should continue to work. This change is experimental and may be
reverted." The `u60` branch still targets 761211; this page is the delta, its impact on Moono, and
a QA plan for a later session. `u60-761211.md` covers the hotfix before it, `u60-inventory.md`
U60 against U59.

Sources:
- Klei's decompiled game code in oni-versioning: `git diff U60-761211 U60-761654` (`50066d31`
  to `7fa0f5b3`), beta against beta, so the diff is code. `u761654:File.cs:N` is a line of
  `OxygenNotIncluded/File.cs` at tag U60-761654.
- `Assembly-CSharp-firstpass.dll` of both builds, decompiled with the same ilspycmd 11.1.0.9782
  (not in oni-versioning). `fp761654:File.cs:N` is a line of that decompile.
- The frozen builds `E:\oni-builds\oni-linux-761211`, `oni-linux-761654`, `oni-win-761211` and
  `oni-win-761654`, each file compared by MD5.
- `tools/AssemblyDiff` (type and member shapes) and `tools/Inventory` (what the game's two
  assemblies reference in Unity, the BCL, firstpass and the libraries) on both Linux builds, and
  every Managed DLL's assembly references and `TargetFrameworkAttribute` read from metadata.
- Klei's patch notes for the build.

## Summary

- **Moono plays 761654.** The published 2026.11.03.02 and `u60` at 1fb784f9 start, load a save
  and play it at speed 3 on Linux and Windows, as the original does on the same install (see
  "Smoke test").
- **One thing is broken: the Windows Restarter.** `App.Restart` now passes the player's command
  line to `Restarter.exe`, and ours refuses more than one argument, so on Windows a restart (Moono
  Tweaks' "Restart to apply", a language change, the mods screen's restart) quits and never comes
  back. Linux is unaffected. Fixed since (see "The Restarter").
- **The .NET Standard 2.1 retarget changes no API we implement.** The game's assemblies and
  Unity's packages now reference `netstandard` 2.1.0.0 where they referenced `mscorlib`, `System`,
  `System.Core` and other BCL assemblies. The BCL in Managed/, Unity's engine modules and the Unity
  version are the same bytes. Every member the game references in Unity, firstpass and the
  libraries is the same set; the BCL members are the same set under another assembly name, plus
  two new ones for the restarter. The packages Moono replaces (uGUI, TextMesh Pro, Timeline) were
  rebuilt with the same public shape.
- **No game tweak breaks.** `fast-sublimation` mirrors a method that changed (cosmetically) and
  needs its verify run; `off-world-fallers` reads a method whose body changed. The rest patch
  nothing that changed.
- **Mods compiled for 761211 that name an `Action` from `AccessCleanUpCollection` (150 there) up get
  the one before it**, in both players: a new action was inserted mid-enum. This includes OniMcp,
  the QA harness's game control mod (`Action.NumActions` as a "no hotkey" value).
- **QA (2026-11-03, `u60` at 4d880346):** W1-W8 and W11-W14 pass against the original, W12 and
  W14 in part; W9 and W10 not run (no fixtures). The Restarter fix holds on Windows and Linux.
  Two BCL differences no D entry listed turned up: fr-FR's group separator (now Mono's,
  ARCHITECTURE D60) and GZip's compressed size (kept, D61). OniMcp's pinned commit does not
  build for U60 (see "QA results").

### Impact on Moono

- **Assembly resolution (`AssemblyPolicy`).** `netstandard` is a framework assembly, so .NET's
  `netstandard.dll` facade answers it before `AssemblyPolicy.Resolve` is asked, as `mscorlib`'s
  facade did; it forwards to `System.Private.CoreLib` and the framework's other assemblies.
  Mono's `netstandard.dll` in Managed/ is never loaded, as `mscorlib.dll` never was. Nothing to
  change. The smoke test and check-types load every game assembly this way.
- **The IL rewriters.** `MonoConversions`, `MonoDirectoryListing`, `MonoThreadAbort`,
  `MonoJitOptimizer`, `NavGridLinksRewrite`, `PathGridPagesRewrite` and `MonoFieldSemantics`
  match methods and member references by name and signature, not by the BCL assembly a reference
  names; their counts are the same on both builds except the one new float conversion.
  `MonoMissingMembers`, `MonoMissingTypes`, `MonoTypeKinds` and `MonoApiGaps` (mods) already treat
  `netstandard` as a BCL scope (`MonoMissingMembers.cs:215`), and `MonoApiGaps.Original` follows the
  type forwarders of Mono's copy in Managed/, which for `netstandard` lead to `mscorlib`, `System`
  and `System.Core`. One spot names `mscorlib` alone: `MonoApiGaps.Original.Has` looks up
  `System.Object` in `mscorlib` for an interface's members, which still holds (Mono's `mscorlib`
  is still in Managed/).
- **The compiled shapes.** Game tweak transpilers match a few call sites each; none of the
  methods whose shape moved is a tweak target, and every tweak installed on 761654 (smoke-test
  log). Mod transpilers that match one of the reshaped methods by IL pattern can stop matching
  in both players alike.
- **Mods compiled against the old target** keep their `mscorlib` and `System*` references, which
  .NET's facades answer as before; nothing in the game they call changed assembly. **Mods compiled
  against the new target** will reference `netstandard` 2.1.0.0. In ours that is the framework's
  facade: every type .NET Standard 2.1 names exists in .NET 10, so such a mod loads. What can differ
  is behaviour where the framework's implementation differs from Mono's, which is the existing list
  of D entries (ARCHITECTURE §2), not new. None exists yet; the QA plan builds one.
- **Unity's packages.** Ours replace `UnityEngine.UI`, `Unity.TextMeshPro` and `Unity.Timeline`
  (`AssemblyPolicy.replacedPackages`); Unity's rebuilt copies have the same public shape, so mods
  compiled against either bind to ours as before. The support packages ours never load
  (`unitySupportPackages`) changed bytes only.
- **Our own assemblies.** `OniMoono.GameTweaks`, E2eDriver and the tests build against the game's
  Managed/ (`OniGameDir`); on the 761654 data they build with no new warnings, and .NET 10
  compiles against an assembly that references `netstandard` without help.

## The Restarter (was broken on Windows)

**Patch note:** "Updated restarter to relaunch the game with command line arguments."

**What changed:** `App.Restart` (fp761654:App.cs:58-75) appended every
`Environment.GetCommandLineArgs()` entry after the first, each quoted, to the Restarter's
arguments, after the executable's path:

```
processStartInfo.Arguments = $"\"{fullPath}\"";
string[] commandLineArgs = Environment.GetCommandLineArgs();
for (int i = 1; i < commandLineArgs.Length; i++)
    processStartInfo.Arguments += $" \"{commandLineArgs[i]}\"";
Debug.LogFormat("Restarter arguments: {0}", processStartInfo.Arguments);
```

Klei's `Restarter.exe` was rebuilt (1,840,128 → 1,832,448 bytes); the Linux `Restarter` is the
same bytes. On Linux the file is `Restarter` (fp761654 Linux build, `RESTART_FILENAME`), on
Windows `Restarter.exe`.

**Impact:**
- **Windows: broken.** `src/OniMoono.Restarter/Program.cs` starts with
  `if (args.Length != 1) { Console.Error.WriteLine("usage: Restarter EXECUTABLE"); return 2; }`.
  In ours, `Environment.GetCommandLineArgs()` is what our native host passed to hostfxr
  (`src/OniMoono.NativeHost/host.c:192`): the host's arguments. A player started from Steam with
  the launch options `setup.ps1` writes, `"…\OniMoono.exe" -- %command%`, always has some, so
  the Restarter gets two or more arguments, prints its usage and exits 2; the player has already
  quit. Checked by running `out/win/host/Restarter.exe` with the executable and two arguments:
  "usage: Restarter EXECUTABLE", exit 2; with one, it starts the executable. Not run in game.
  Affected: Moono Tweaks' "Restart to apply" (`MoonoTweaksMenu.cs:796`), a language change, the
  mods screen's restart.
- **Linux: unaffected.** `src/OniMoono.Host/Restarter` reads `$1` and takes the rest from
  `ONI_MOONO_RESTART_ARGS`; the new arguments are ignored.
- **Fixed:** the Restarter takes `EXECUTABLE [ARGUMENT...]` (`RestartCommand`): the host's
  `ONI_MOONO_RESTART_ARGV` wins, since Klei's quoting (`"` around each argument, no escaping of
  inner quotes) loses an argument that ends in a backslash or holds a quote; without it the
  command line's arguments are used. Measured with a probe target, Klei's 761654 `Restarter.exe`
  starts the executable at once (no wait for the old process), in the executable's folder, with
  the arguments in .NET's quoting; 761211's and 744825's start it at once with none. Ours writes
  the same command line, still waits for the player and keeps its working folder. A Moono Tweaks
  "Restart to apply" on Windows (Vulkan, `--gc low-memory --dxgi on -- …\OxygenNotIncluded.exe`)
  came back with the same command line and the new setting on 761654 and 761211.
